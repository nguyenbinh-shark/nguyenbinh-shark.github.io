    Ngoài lề: Shark Drive Copier — copy thư mục Google Drive mà không tải về máy Side project: Shark Drive Copier — server-side Google Drive folder copies

    11 phút đọcminute read

    Ngày đăng:Published: 09/10/2026October 09, 2026

    Mục lục bài viếtOn this page

      Một bài ngoài lề giữa những bài điều khiển và robot: khi nhận một thư mục tài liệu được chia sẻ trên Google Drive, đôi lúc mình muốn giữ một bản riêng trong Drive của mình. Nếu tải toàn bộ về máy rồi tải lên lại, máy phải làm trung gian cho một lượng dữ liệu có thể khá lớn.

      Shark Drive Copier là tiện ích Chrome mình viết cho việc đó. Bạn đưa link nguồn, chọn thư mục đích rồi bấm Bắt đầu. Extension gửi yêu cầu tạo bản sao bằng Drive API v3 files.copy; nội dung file được sao chép trên Google, không download/upload qua máy của bạn. Với thư mục, extension tạo cây thư mục đích rồi copy từng file bên trong.

      Tải mã nguồn và hướng dẫn

      • Tải mã nguồn Shark Drive Copier v1.0.1 — ZIP.
      • Tải hướng dẫn đầy đủ — Markdown.
      • Logo SVG để xem hoặc chỉnh sửa.

      Hiện chưa có bản trên Chrome Web Store. Gói ZIP là mã nguồn, không phải gói cài một chạm. Người tự build cần cấu hình OAuth một lần; sau đó sử dụng bằng giao diện. Gói không chứa access token, client secret, cấu hình OAuth riêng hay thư mục node_modules.

      1. Tiện ích làm được gì?

      Giao diện chính nằm ở side panel, tức khung bên cạnh trang web. Các điểm vào gồm icon extension, nút nổi Copy vào Drive của tôi trên trang file/thư mục Drive và menu chuột phải trên link Drive.

      Thao tácKết quả
      Copy một fileTạo bản sao trong My Drive hoặc thư mục đích đã chọn
      Copy một thư mụcTạo cây thư mục tương ứng, duyệt và copy file con
      Tạm dừng / Tiếp tụcGiữ trạng thái công việc để xử lý tiếp
      HuỷNgừng công việc; giữ những bản sao đã tạo
      Xuất log .txtLưu danh sách lỗi và metadata để kiểm tra

      File mà chủ sở hữu chặn copy sẽ được bỏ qua và ghi lỗi. Shortcut được đi theo tới đối tượng thật; mỗi ID được xử lý một lần trong một job. Vì vậy, hai shortcut trỏ cùng file không tạo hai bản sao ở hai vị trí khác nhau. Đây là công cụ tạo bản sao nội dung và cấu trúc thư mục, không phải hệ thống sao lưu mọi quyền chia sẻ, lịch sử phiên bản hay mọi metadata.

      2. Build và cài vào Chrome

      Cần Google Chrome 116 trở lên và Node.js tương thích với project: ^22.12.0, ^24.0.0 hoặc >=26.0.0. Bản này dùng chrome.identity.getAuthToken, chưa có luồng đăng nhập thay thế cho Edge/Brave.

      Giải nén ZIP, mở terminal trong thư mục drive-copier, chạy lần lượt:

      npm i
npm run build

      Mở chrome://extensions, bật Developer mode, chọn Load unpacked rồi chọn thư mục dist vừa được tạo. Ghim icon Shark Drive Copier trên thanh công cụ và ghi lại ID trên thẻ extension.

      Bản build đầu tiên có Client ID placeholder nên chưa đăng nhập được. Public key mẫu hợp lệ giúp ID giữ nguyên qua các lần build. Không thay key bằng một chuỗi tên tùy ý.

      3. Cấu hình đăng nhập Google một lần

      Theo quy trình OAuth cho Chrome extension, OAuth Client phải gắn với đúng ID extension đang chạy.

      1. Tạo project trong Google Cloud Console, bật Google Drive API trong APIs & Services → Library.
      2. Trong Google Auth Platform, cấu hình tên ứng dụng ở Branding; chọn External / Testing ở Audience, thêm email sử dụng vào Test users.
      3. Ở Data Access, thêm scope https://www.googleapis.com/auth/drive.
      4. Chọn Clients → Create client → Chrome Extension. Điền Item ID bằng ID lấy từ chrome://extensions, rồi copy Client ID.
      5. Copy extension.config.example.json thành extension.config.json. Chỉ thay trường clientId bằng Client ID vừa tạo; giữ nguyên key.
      6. Chạy lại npm run build, đóng side panel, bấm Reload trên thẻ extension và tải lại tab Drive.

      Project dùng scope drive vì cần duyệt các file con được chia sẻ từ link nguồn; scope drive.file không cung cấp quyền truy cập tùy ý vào toàn bộ cây đó. Scope drive thuộc nhóm restricted. Đưa ứng dụng ra dùng rộng rãi cần xử lý OAuth verification; yêu cầu security assessment còn phụ thuộc cách ứng dụng truy cập và xử lý dữ liệu. Xem phân loại scope Drive và hướng dẫn chi tiết trong gói tải xuống.

      Nếu muốn tạo key riêng, chạy npm run keygen trước khi đăng ký OAuth Client. Đổi key làm đổi ID extension và cần cập nhật OAuth tương ứng. Khi lên Chrome Web Store, dùng ID/public key của item trên Store thay vì mặc định cho rằng ID phát triển sẽ trùng.

      4. Copy thư mục đầu tiên

      Nên thử trước với một thư mục nhỏ có vài file, một thư mục con và một shortcut.

      1. Mở side panel → Đăng nhập, hoàn tất cửa sổ cấp quyền. Kiểm tra email hiển thị là tài khoản muốn nhận bản sao.
      2. Dán Link hoặc ID nguồn, chẳng hạn https://drive.google.com/drive/folders/ID_THU_MUC.
      3. Để trống Thư mục đích nếu muốn copy vào My Drive. Nếu chọn đích khác, nhập link/ID thư mục mà tài khoản có quyền thêm file. Đích không được trùng hoặc nằm trong thư mục nguồn.
      4. Tên mới chỉ đổi tên file/thư mục gốc của bản sao; có thể bỏ trống.
      5. Bấm Bắt đầu, theo dõi số file đã copy/đã phát hiện, số thư mục và đường dẫn đang xử lý.
      6. Khi hoàn tất, bấm Mở kết quả trong Google Drive. Mở danh sách lỗi để kiểm tra những mục bị bỏ qua.

      Tổng số file tăng dần khi duyệt cây nên phần trăm có thể giảm trong lúc chạy. Những job thêm sau vào hàng chờ; tại một thời điểm chỉ có một job chạy. Đóng side panel không huỷ job, nhưng Chrome phải còn chạy để tiếp tục xử lý.

      Tạm dừng và Huỷ không thu hồi request đã gửi: một vài bản sao có thể hoàn tất sau thao tác đó. Huỷ cũng không xóa thư mục kết quả. Sau Đăng xuất, job không tự xin lại token để chạy tiếp; cần đăng nhập đúng tài khoản tạo job.

      5. Worker bị tắt thì sao?

      Service worker là phần chạy nền của extension. Chrome có thể dừng nó, nên engine lưu hàng đợi thư mục, page token, ánh xạ thư mục, ID file đã copy, bộ đếm và lỗi vào chrome.storage.local sau mỗi bước nhỏ. Alarm đánh thức worker mỗi phút khi cần chạy.

      Một điểm khó là Google có thể copy xong nhưng worker chưa kịp lưu kết quả. Extension gắn mã thao tác vào appProperties của bản sao và đối soát mã đó khi resume. Nếu chưa xác định được kết quả, job tạm dừng để tránh gửi lại một request có thể đã thành công. Cơ chế này không phải giao dịch nguyên tử giữa Google và Chrome, nên không hứa bảo đảm tuyệt đối không trùng dưới mọi lỗi mạng.

      6. Khi đăng nhập hoặc copy gặp lỗi

      Triệu chứngViệc cần kiểm tra
      Báo chưa cấu hình OAuthĐiền Client ID, build lại và Reload extension
      OAuth bị từ chốiLoại client phải là Chrome Extension; Item ID đúng; email đã nằm trong Test users
      Vẫn thấy thông báo lỗi cũĐóng panel, Reload đúng thư mục dist, tải lại Drive; bản này hiện v1.0.1 ở cuối panel
      Không kết nối được DriveĐọc nguyên nhân trong ngoặc; kiểm tra mạng, VPN/proxy hoặc extension chặn kết nối
      API trả 403/404Kiểm tra quyền nguồn/đích bằng chính tài khoản hiển thị trong panel; kiểm tra Drive API đã bật
      Hết dung lượng hoặc chạm quotaGiải phóng dung lượng/chờ hạn mức làm mới; kiểm tra các bản sao đã tạo
      Kết quả request chưa xác địnhXem thư mục kết quả và log; dùng Tiếp tục để đối soát, tránh tạo job mới ngay

      Một lỗi đã gặp khi phát triển là gọi native fetch như phương thức của đối tượng client: Chrome báo Illegal invocation, nhưng thông báo cũ che mất nguyên nhân. Bản này bind fetch với globalThis, giữ chi tiết lỗi kết nối và rút ngắn retry ở bước đọc tài khoản để giao diện không chờ quá lâu.

      Google tài liệu hóa giới hạn khoảng 750 GB/ngày tổng upload và copy cho tài khoản Workspace, cùng các hạn mức khác. Server-side không có nghĩa bỏ qua quota hay giới hạn của chủ sở hữu. Xem hạn mức Drive API.

      7. Mã nguồn và mức kiểm tra hiện tại

      Project dùng TypeScript + Vite, không có framework UI nặng hay remote code:

      src/background/       Worker, hàng chờ, alarm và thông báo
src/sidepanel/        Giao diện tiếng Việt, dark mode, tiến độ và log
src/content/          Nút nổi, Shadow DOM và điều hướng SPA của Drive
src/lib/driveClient.ts Fetch, auth, retry và đối soát bản sao
src/lib/copyEngine.ts  Duyệt BFS, phân trang, shortcut, tối đa 4 copy đồng thời
src/lib/store.ts       Lưu checkpoint
src/lib/parseLink.ts   Đọc ID và resource key từ link

      Chạy npm test để kiểm tra các ca parse link, phân trang, shortcut, pause/resume, phục hồi sau khi Google copy xong, retry 429, giới hạn đồng thời và hàng chờ. Tại thời điểm đóng gói, 74 test pass và build TypeScript/Vite thành công. Extension unpacked và lỗi binding fetch đã được kiểm tra trong Chrome thử nghiệm; đây chưa phải xác nhận mọi kịch bản copy trên tài khoản Drive thật. Hãy kiểm tra bản sao của thư mục nhỏ trước khi dùng với dữ liệu lớn.

      Token không được ghi vào state hoặc log. State cục bộ và log có thể chứa email, ID, tên file và đường dẫn; log tải về là văn bản metadata, không phải nội dung file nguồn. Trình duyệt lưu trạng thái cục bộ có dung lượng giới hạn, nên cây quá lớn hoặc log quá nhiều có thể khiến job phải dừng.

      English quick start

      Shark Drive Copier is a Chrome side project that requests server-side copies of shared files and folder trees. Download the source ZIP, extract it, and run npm i and npm run build inside drive-copier. Load dist through chrome://extensions in Developer mode.

      The source package deliberately contains an OAuth placeholder. Configure your own Google Cloud project, enable Drive API, add a test user and the Drive scope, and register a Chrome Extension OAuth client for the loaded extension ID. Copy the example config, replace its Client ID, retain the public key, rebuild and reload. See the full Vietnamese guide.

      Sign in, paste a source link, optionally choose a destination folder and a new root name, then click Bắt đầu (Start). Tạm dừng / Tiếp tục / Huỷ mean Pause / Resume / Cancel. Copies already created remain after cancellation. Review skipped-item logs and the resulting Drive folder.

      This is currently an unpacked development release, not a Chrome Web Store installation. Tests use mock APIs; ambiguous mutation results pause for reconciliation instead of blindly copying again.
