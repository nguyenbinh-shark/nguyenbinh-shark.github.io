    Ở Bài 1, chúng ta đã viết 30 dòng PID đầu tiên. Thuật toán chạy mượt trên lý thuyết. Nhưng khi nạp vào vi điều khiển thực tế, hệ thống bắt đầu phát bệnh: lò sấy bị nung vượt nhiệt độ đặt, động cơ rung giật và CPU bị nghẽn vì hàm chờ.

    Toán học không có giới hạn, nhưng phần cứng thì có. Bài viết này mổ xẻ 5 căn bệnh kinh điển của PID đầu tay và đưa ra 5 toa thuốc bằng C++ để chữa dứt điểm từng bệnh.

    1. Bệnh 1: Bão hòa đầu ra (Output Saturation)

    Triệu chứng & Nguyên nhân

    Khi còn xa mục tiêu, phép tính $K_p \times e$ có thể đòi công suất $+300\%$. Nhưng lò sấy chỉ nhận tối đa 100%, và chân PWM của Arduino chỉ nhận giá trị từ $0$ đến $255$. Xuất số vượt ngưỡng sẽ làm tràn số và sai lệch chấp hành.

    Cặp Công thức & Toa thuốc

    \[u_{\text{sat}}(t) = \text{clamp}(u(t), u_{\text{min}}, u_{\text{max}})\]
    // Toa thuốc 1: Cắt ngọn đầu ra trong giới hạn vật lý
output = constrain(output, 0.0, 100.0); // Khống chế 0 - 100%

    Hàm constrain(x, a, b) giữ giá trị luôn nằm trong đoạn $[a, b]$, bảo vệ phần cứng khỏi những mệnh lệnh quá tải.

    2. Bệnh 2: Phình sổ nợ — Hiện tượng Integral Windup

    Triệu chứng & Nguyên nhân

    Khi đặt đích 60°C, lò cần thời gian gia nhiệt. Dù lò đã chạy hết công suất 100%, nhiệt độ vẫn chưa tới đích ($e > 0$).

    Dòng lệnh I_term += Ki * error * dt của Chương 4 cứ miệt mài ghi thêm nợ. Khi nhiệt độ vừa chạm đích ($e = 0$), cuốn sổ nợ đã phình to tới $+150$. Dù sai số bằng 0, khoản nợ khổng lồ vẫn ép lò nung tối đa làm nhiệt độ vọt lố lên 75°C.

    Trên đồ thị mô phỏng MATLAB:

    • Đồ thị 1 (Sai số $e(t)$ có nhiễu): Tín hiệu đo từ cảm biến thực tế luôn có nhiễu cao tần li ti dập dờn quanh giá trị thật.
    • Đồ thị 3 (Khâu I - Bão hòa tích phân): Khi sai số tồn tại lâu, đường màu xanh tiếp tục tích lũy vượt xa đường nét đứt đỏ (ngưỡng vật lý MAX = 5). Khoản tích lũy dư thừa vô ích này chính là nguyên nhân khiến hệ thống bị kẹt cứng ở công suất đỉnh và vọt lố nghiêm trọng khi đối tượng bắt đầu đổi chiều.

    Cặp Công thức & Toa thuốc

    Ta lập hai lớp bảo vệ: khống chế trần sổ nợ (IntegralLimit) và kẹp điều kiện tích phân (Clamping — ngừng cộng nợ khi đầu ra đã chạm trần).

    \[I_k = \begin{cases} I_{k-1} + K_i e_k \Delta t & \text{khi chưa bão hòa} \\ I_{k-1} & \text{khi đã bão hòa và cùng chiều} \end{cases}\]
    // Toa thuốc 2: Kẹp sổ nợ chống Windup (Anti-windup Clamping)
bool is_saturated = (output >= 100.0 && error > 0) || (output <= 0.0 && error < 0);
if (!is_saturated) {
  I_term += Ki * error * dt;
}
I_term = constrain(I_term, -I_MAX, I_MAX); // Giới hạn trần sổ nợ

    3. Bệnh 3: Phanh bị giật — Nhiễu cảm biến và bộ lọc khâu D

    Triệu chứng & Nguyên nhân

    Khâu vi phân $D$ ở Chương 5 tính bằng độ dốc sai số chia cho $\Delta t$:

    \[D = K_d \frac{e_k - e_{k-1}}{\Delta t}\]

    Nhiễu ADC nhảy nhót $\pm 0.5^\circ\text{C}$ trong $\Delta t = 0.05\,\text{s}$ sẽ tạo xung ảo tới $10^\circ\text{C}/\text{s}$. Như bạn thấy ở đồ thị thứ 2 trong hình mô phỏng MATLAB phía trên (Khâu D: Khuếch đại nhiễu cực độ), các rung lắc li ti của cảm biến bị nhân với $1/\Delta t$ biến thành những cú giật có biên độ lên tới $\pm 20$, khiến động cơ rung bần bật và phát tiếng kêu è è.

    Cặp Công thức & Toa thuốc

    Bộ lọc thực chất thuộc phạm trù xử lý tín hiệu (Signal Processing) — một mảng kiến thức lớn sẽ được chúng ta làm rõ ở các series chuyên sâu khác (như bộ lọc Kalman, AHRS hay lọc số IIR). Nhưng ở góc độ điều khiển PID thực chiến, một bộ lọc thông thấp bậc một (First-order Low-pass Filter) là liều sơ cứu tức thời và hiệu quả nhất để gạt bỏ gai nhọn:

    \[D_{\text{filt}}(k) = \alpha \cdot D_{\text{raw}}(k) + (1 - \alpha) \cdot D_{\text{filt}}(k-1)\]
    // Toa thuốc 3: Lọc thông thấp sơ cứu cho khâu D
float D_raw = Kd * (error - previous_error) / dt;
float alpha = 0.25; // Hệ số lọc mượt (0.0 đến 1.0)
D_filtered = alpha * D_raw + (1.0 - alpha) * D_filtered;

    Quan sát đồ thị MATLAB so sánh ở trên:

    • Đường màu hồng (D thô): Rung lắc dữ dội quanh mức 0, làm hao phí năng lượng và gây mòn cơ khí.
    • Đường màu đỏ (D sau lọc): Tín hiệu phẳng lặng, êm ái khi không có chuyển động lớn.
    • Đặc tính giữ nhịp: Khi xuất hiện bước nhảy thực sự tại $t=1\text{s}$ và $t=6\text{s}$, khâu D sau lọc vẫn phát ra xung phản lực phanh hãm kịp thời và sắc sảo, không hề bị trễ nhịp điều khiển.

    Nguyên lý vàng: Để hệ thống điều khiển vận hành xuất sắc, bên cạnh việc tinh chỉnh bộ thông số $K_p, K_i, K_d$ chuẩn, điều kiện tiên quyết là phải có tín hiệu phản hồi và đầu vào đo lường đạt chất lượng tốt (sạch nhiễu, đúng nhịp). “Đầu vào rác thì đầu ra rác” (Garbage In, Garbage Out).

    4. Bệnh 4: Loạn nhịp $\Delta t$ và chia cho 0

    Triệu chứng & Nguyên nhân

    Ở nhịp đầu sau khi bật nguồn, previous_time = 0 làm $\Delta t$ vọt lên hàng triệu. Ngoài ra, nếu hàm bị gọi 2 lần sát nhau thì $\Delta t = 0$ gây lỗi chia cho không (NaN/Inf).

    Toa thuốc bằng Code

    // Toa thuốc 4: Khởi tạo mốc thời gian và chặn lỗi dt
if (previous_time == 0) {
  previous_time = current_time;
  previous_error = error;
  return 0.0; // Bỏ qua nhịp đầu để lấy mốc
}

float dt = (current_time - previous_time) / 1000.0;
if (dt <= 0.0 || dt > 0.5) dt = 0.05; // Mốc an toàn 50ms

    5. Bệnh 5: delay() làm nghẽn CPU

    Triệu chứng & Nguyên nhân

    Lệnh delay(50) bắt vi điều khiển đứng yên. CPU không thể đọc nút bấm, nhận lệnh Serial hay cập nhật màn hình hiển thị.

    Toa thuốc bằng Code

    Lập lịch không nghẽn (Non-blocking Timer) bằng millis():

    // Toa thuốc 5: Lập lịch chu kỳ bằng millis() không nghẽn
unsigned long last_pid_time = 0;
const unsigned long PID_INTERVAL = 50; // Chu kỳ lấy mẫu 50ms

void loop() {
  unsigned long now = millis();
  if (now - last_pid_time >= PID_INTERVAL) {
    last_pid_time = now;
    float temperature = readTemperature();
    float power = computePID(60.0, temperature);
    analogWrite(HEATER_PIN, power);
  }

  // CPU rảnh tay xử lý tác vụ khác:
  handleButtons();
  updateScreen();
}

    6. Bản code PID hoàn chỉnh sau khi chữa bệnh (Bản V2)

    Gộp cả 5 toa thuốc, ta có hàm PID chuẩn mực:

    // Cấu hình thông số và biến trạng thái
float Kp = 2.0, Ki = 0.35, Kd = 0.8;
float I_term = 0.0, previous_error = 0.0, D_filtered = 0.0;
unsigned long previous_time = 0;

const float OUT_MIN = 0.0, OUT_MAX = 100.0; // Giới hạn công suất
const float I_MAX = 25.0;                   // Giới hạn sổ nợ
const float ALPHA = 0.25;                   // Hệ số lọc D

float computePID_v2(float setpoint, float input) {
  unsigned long current_time = millis();
  float error = setpoint - input;

  // Toa thuốc 4: Bảo vệ nhịp dt
  if (previous_time == 0) {
    previous_time = current_time;
    previous_error = error;
    return 0.0;
  }
  float dt = (current_time - previous_time) / 1000.0;
  if (dt <= 0.0 || dt > 0.5) dt = 0.05;

  // 1. Khâu P
  float P_term = Kp * error;

  // 2. Khâu D kèm Toa thuốc 3 (Lọc thông thấp)
  float D_raw = Kd * (error - previous_error) / dt;
  D_filtered = ALPHA * D_raw + (1.0 - ALPHA) * D_filtered;

  // 3. Khâu I kèm Toa thuốc 2 (Anti-windup Clamping)
  float tentative_output = P_term + I_term + D_filtered;
  bool is_saturated = (tentative_output >= OUT_MAX && error > 0) ||
                      (tentative_output <= OUT_MIN && error < 0);
  if (!is_saturated) {
    I_term += Ki * error * dt;
  }
  I_term = constrain(I_term, -I_MAX, I_MAX);

  // 4. Khâu tổng ngõ ra kèm Toa thuốc 1 (Bão hòa đầu ra)
  float output = P_term + I_term + D_filtered;
  output = constrain(output, OUT_MIN, OUT_MAX);

  // Cập nhật trạng thái
  previous_error = error;
  previous_time = current_time;
  return output;
}
