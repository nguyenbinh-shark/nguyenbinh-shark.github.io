    Ở Bài 2, chúng ta đã dùng các khối lệnh điều kiện để kê 5 toa thuốc bảo vệ phần cứng. Nhưng việc dựa vào rào chắn bên ngoài chỉ mới chữa triệu chứng mà chưa tối ưu từ gốc thuật toán.

    Các kỹ sư chuyên nghiệp tiếp cận vấn đề sâu hơn: nâng độ chính xác vi tích phân số ngay từ phương trình cốt lõi. Bài viết này áp dụng 3 kỹ thuật tinh chỉnh kinh điển từ thư viện mã nguồn mở nổi tiếng WangHongxi2001/PID_Library để biến bộ code PID trở nên mượt mà và thông minh vượt trội.

    1. Tinh chỉnh 1: Tích phân hình thang (Trapezoidal / Tustin Integral)

    Vấn đề của tích phân chữ nhật

    Ở Bài 1, khâu $I$ tính bằng tích phân chữ nhật: $I_{\text{step}} = K_i \cdot e_k \cdot \Delta t$. Khi tần số lấy mẫu thấp ($\Delta t$ lớn), các cột hình chữ nhật tạo khoảng hở tam giác sai lệch so với diện tích thực dưới đường cong.

    Giải pháp hình thang Tustin

    Thay vì lấy chiều cao là sai số của riêng nhịp hiện tại, ta lấy trung bình cộng của hai nhịp liên tiếp $(e_k + e_{k-1}) / 2$. Diện tích mỗi mảnh ghép trở thành một hình thang ôm sát đường cong:

    \[I_{\text{step}} = K_i \cdot \frac{e_k + e_{k-1}}{2} \cdot \Delta t\]
    // Tinh chỉnh 1: Tích phân hình thang Tustin
float I_step = Ki * 0.5f * (error + previous_error) * dt;
I_term += I_step;

    Phép tính này giúp cuốn sổ nợ tích lũy diện tích chuẩn xác hơn nhiều lần mà không làm tăng tải tính toán của CPU.

    2. Tinh chỉnh 2: Biến tốc độ tích phân (Changing Integral Rate)

    Vấn đề: Khi nào nên “ghi nợ”?

    Hãy tưởng tượng bạn đang lái xe từ xa lộ vào ga-ra:

    • Khi còn cách đích 10 km (sai số lớn): Bạn chỉ cần đạp ga mạnh (vai trò của khâu $P$) để xe chạy nhanh. Lúc này hoàn toàn chưa cần đến khâu $I$. Nếu khâu $I$ cứ miệt mài cộng dồn nợ từ lúc còn ở xa lộ, cuốn sổ nợ sẽ phình to khủng khiếp, khiến xe lao thẳng qua cửa ga-ra (vọt lố).
    • Khi xe đã vào trong ga-ra và cách vạch đỗ 10 cm (sai số nhỏ): Khâu $P$ lúc này gần như hết lực. Đây mới là lúc khâu $I$ phát huy giá trị tối thượng: soi từng milimet sai số còn sót lại để kéo xe khít vào vạch.

    Nếu ngắt/bật khâu $I$ một cách đột ngột (như phương pháp tách tích phân cổ điển), hệ thống sẽ bị giật nảy khi đi qua ranh giới bật tắt.

    Giải pháp WangHongxi: Điều biến tốc độ mượt mà

    WangHongxi đưa vào một hệ số điều biến $f(e) \in [0, 1]$ dựa trên độ lớn của sai số $|e|$, chia hành trình làm 3 vùng thông qua hai tham số ngưỡng $A$ và $B$:

    Ví dụ thực tế: Xét bài toán điều khiển nhiệt độ lò sấy với giá trị đặt $SP = 60^\circ\text{C}$, ta chọn $B = 5^\circ\text{C}$ và $A = 20^\circ\text{C}$ (ngưỡng chuyển tiếp $A + B = 25^\circ\text{C}$):

    Phân vùngĐiều kiện sai sốNhiệt độ lò thực tếHệ số điều biến $f(e)$Tác động lên khâu tích phân (I)
    Vùng 1 — Xa xôi$\lvert e\rvert \ge 25^\circ\text{C}$Dưới $35^\circ\text{C}$$f(e) = 0$Khâu I tắt hoàn toàn, nhường đường cho khâu P gia nhiệt tối đa
    Vùng 2 — Chuyển tiếp$5^\circ\text{C} < \lvert e\rvert < 25^\circ\text{C}$Từ $35^\circ\text{C}$ đến $55^\circ\text{C}$$f(e) = \frac{20 - \lvert e\rvert + 5}{20}$Khâu I tăng dần từ 0 lên 1, tham gia từ từ không gây giật cục
    Vùng 3 — Cập bến$\lvert e\rvert \le 5^\circ\text{C}$Trên $55^\circ\text{C}$$f(e) = 1$Khâu I mở $100\%$ công lực để xóa sạch sai số xác lập

    Hàm toán học điều biến tổng quát:

    \[\begin{aligned} f(e) = \begin{cases} 0 & \text{khi } \lvert e\rvert \ge A+B \\ \frac{A - \lvert e\rvert + B}{A} & \text{khi } B < \lvert e\rvert < A+B \\ 1 & \text{khi } \lvert e\rvert \le B \end{cases} \end{aligned}\]
    // Tinh chỉnh 2: Biến tốc độ tích phân (Changing Integral Rate)
float factor = 1.0f;
float abs_e = abs(error);

if (abs_e >= (ScalarA + ScalarB)) {
  factor = 0.0f; // Vùng 1: Quá xa, ngắt tích phân
} else if (abs_e > ScalarB) {
  factor = (ScalarA - abs_e + ScalarB) / ScalarA; // Vùng 2: Chuyển tiếp mượt
} // Vùng 3: Áp sát đích, factor giữ nguyên = 1.0f

// Lượng tích phân được điều biến theo khoảng cách
I_term += factor * Ki * 0.5f * (error + previous_error) * dt;

    Nhờ cơ chế này, hệ thống triệt tiêu hoàn toàn lượng nợ tích lũy vô ích lúc khởi động, giúp lò sấy tăng nhiệt êm ái và cập bến đích chuẩn xác mà không bị vọt lố.

    3. Tinh chỉnh 3: Vi phân theo giá trị đo (Derivative on Measurement)

    Cú sốc Derivative Kick

    Khâu vi phân $D$ truyền thống tính theo tốc độ thay đổi của sai số:

    \[D = K_d \frac{d(Target - Input)}{dt} = K_d \left( \frac{d Target}{dt} - \frac{d Input}{dt} \right)\]

    Khi người dùng vặn núm điều khiển đổi Setpoint đột ngột từ 30°C lên 60°C, giá trị $Target$ nhảy bậc trong tích tắc. Đạo hàm $\frac{d Target}{dt}$ trở thành một con số khổng lồ, tạo ra một đỉnh nhọn cực đại (Derivative Kick) đánh thẳng vào đầu ra PID. Cơ cấu chấp hành sẽ bị giật nảy một cú rất mạnh dù lò sấy chưa hề thay đổi trạng thái vật lý.

    Giải pháp: Loại bỏ đạo hàm của Setpoint

    Trong hầu hết thời gian vận hành, giá trị đặt $Target$ là một hằng số cố định, tức $\frac{d Target}{dt} = 0$. Vì vậy, ta loại bỏ hoàn toàn $Target$ ra khỏi phép tính vi phân và chỉ giữ lại đạo hàm của giá trị đo $Input$ (với dấu âm đảo ngược):

    \[D(k) = -K_d \frac{Input(k) - Input(k-1)}{\Delta t} = K_d \frac{Input(k-1) - Input(k)}{\Delta t}\]
    // Tinh chỉnh 3: Vi phân theo giá trị đo (Derivative on Measurement)
float D_term = Kd * (previous_input - input) / dt;

    Khâu $D$ lúc này hoạt động đúng bản chất: lực hãm chỉ kích hoạt khi bản thân vật thể đang chuyển động quá nhanh, hoàn toàn miễn nhiễm với các cú vặn núm Setpoint đột ngột của con người.

    4. Bản code PID hoàn chỉnh sau 3 tinh chỉnh (Bản V3)

    Gộp cả 3 tinh chỉnh cùng các đai an toàn của Bài 2, chúng ta có phiên bản PID V3 chuẩn mực công nghiệp:

    // Thông số điều khiển và biến trạng thái
float Kp = 2.0, Ki = 0.35, Kd = 1.2;
float ScalarA = 20.0, ScalarB = 5.0; // Ngưỡng biến tốc độ tích phân
float I_term = 0.0, previous_error = 0.0, previous_input = 0.0;
unsigned long previous_time = 0;

const float OUT_MIN = 0.0, OUT_MAX = 100.0;
const float I_MAX = 25.0;

float computePID_v3(float setpoint, float input) {
  unsigned long current_time = millis();
  float error = setpoint - input;

  // Bảo vệ nhịp dt
  if (previous_time == 0) {
    previous_time = current_time;
    previous_error = error;
    previous_input = input;
    return 0.0;
  }
  float dt = (current_time - previous_time) / 1000.0;
  if (dt <= 0.0 || dt > 0.5) dt = 0.05;

  // 1. Khâu P
  float P_term = Kp * error;

  // 2. Khâu I: Tích phân hình thang Tustin + Biến tốc độ tích phân
  float factor = 1.0f;
  float abs_e = abs(error);
  if (abs_e >= (ScalarA + ScalarB)) factor = 0.0f;
  else if (abs_e > ScalarB) factor = (ScalarA - abs_e + ScalarB) / ScalarA;

  float I_step = factor * Ki * 0.5f * (error + previous_error) * dt;
  I_term += I_step;
  I_term = constrain(I_term, -I_MAX, I_MAX); // Anti-windup limit

  // 3. Khâu D: Vi phân theo giá trị đo (Derivative on Measurement)
  float D_term = Kd * (previous_input - input) / dt;

  // 4. Tổng ngõ ra kèm cắt bão hòa
  float output = P_term + I_term + D_term;
  output = constrain(output, OUT_MIN, OUT_MAX);

  // Cập nhật trạng thái
  previous_error = error;
  previous_input = input;
  previous_time = current_time;
  return output;
}
