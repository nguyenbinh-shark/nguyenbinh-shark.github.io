    RPBot Studio — vận hành Mapping và Navigation của robot từ PC RPBot Studio — run robot Mapping and Navigation from a PC

    Ngày đăng:Published: 18/10/2026October 18, 2026

    RPBot Studio là ứng dụng desktop để vận hành robot RPBot (Raspberry Pi 5, STM32H723, RPLidar, ROS 2 Jazzy) từ máy tính: tạo bản đồ, chạy Navigation, quản lý map đã lưu, theo dõi cảm biến và dừng tác vụ trên robot. Studio không bao giờ gửi lệnh vận tốc hay lệnh bật động cơ.RPBot Studio is a desktop app for running the RPBot robot (Raspberry Pi 5, STM32H723, RPLidar, ROS 2 Jazzy) from a computer: build maps, run Navigation, manage saved maps, watch the sensors and stop robot tasks. Studio never sends velocity or motor-enable commands.

    Tính năng

    • Tự kết nối: kiểm tra SSH tới Pi, tìm phiên Mapping/Navigation đang chạy, tự lấy ROS domain và cấu hình Fast DDS của phiên đó, rồi tự nối lại khi mạng chập chờn.
    • Bảng trạng thái luôn hiển thị: kết nối, chế độ, map, Nav2, motor, các ô LiDAR, Odom, IMU, Motor FB và vận tốc v, ω, cập nhật khoảng 5 lần/giây. Dữ liệu cũ hơn 2 giây bị đánh dấu là cũ thay vì tiếp tục hiện số đo lỗi thời.
    • Mapping: bắt đầu phiên, mở RViz đã cấu hình sẵn, lưu map trên Pi, tạo map lại, dừng phiên.
    • Bản đồ đã lưu: danh sách kèm ảnh xem trước; tải về PC có kiểm tra checksum; đổi tên; chuyển vào thùng rác. Không thao tác nào ghi đè file sẵn có.
    • Navigation: chạy Nav2 trên map đã chọn, mở RViz Navigation để đặt vị trí ban đầu và chọn đích.
    • Tác vụ và Debug: xem, dừng các launch/bag đang chạy; xem tuổi dữ liệu từng topic; đọc log dịch vụ trên robot.
    • Tiếng Việt / English đổi ngay khi đang chạy.

    Hệ thống cần có

    Thành phầnYêu cầu
    PC WindowsWindows 10/11 x64; WSL 2 với Ubuntu 24.04 và ROS 2 Jazzy có RViz; SSH key trong WSL
    PC LinuxUbuntu 24.04 trở lên, x86_64; ROS 2 Jazzy có RViz; ssh
    RobotRaspberry Pi 5, Ubuntu 24.04, ROS 2 Jazzy; workspace ~/pi5-stm32-slam đã build (SLAM Toolbox, Nav2, PyYAML); STM32 chạy firmware Microros_H723_USB

    [!IMPORTANT] Cần biết trước khi cài

    Studio điều khiển phần mềm phía robot của RPBot. Workspace pi5-stm32-slam trên Pi hiện chưa phát hành công khai. Nếu robot của bạn dùng stack ROS 2 khác, đọc mục Dùng với robot khác để biết Studio cần những gì.

    Bắt đầu nhanh

    1. Cài ROS 2 Jazzy có RViz trên PC. Trên Windows, ROS chạy trong WSL 2.
    2. Tạo SSH key và chép lên Pi, đăng nhập thử một lần để chấp nhận host key.
    3. Tải RPBot Studio cho hệ điều hành của bạn ở khung phía trên và mở app.
    4. Vào trang Kết nối, nhập tên hoặc IP của Pi và tài khoản SSH, bấm Kết nối ngay.
    5. Tạo map ở trang Mapping, lưu map, rồi chạy Navigation trên map đó.

    Các mục dưới đây trình bày chi tiết từng bước.

    1. Chuẩn bị PC

    Windows. Mở PowerShell bằng quyền Administrator để cài Ubuntu 24.04 trong WSL:

    wsl --install -d Ubuntu-24.04

    Trong Ubuntu, cài ROS 2 Jazzy theo hướng dẫn chính thức của ROS 2 với gói ros-jazzy-desktop; gói này đã có RViz.

    Nên bật chế độ mạng mirrored của WSL để WSL nhận được gói DDS từ Pi. Chế độ này cần Windows 11 22H2 trở lên; trên Windows 10, WSL dùng mạng NAT nên dữ liệu ROS từ Pi thường không tới được Studio dù SSH vẫn chạy. Tạo hoặc sửa file %UserProfile%\.wslconfig:

    [wsl2]
networkingMode=mirrored

    Sau đó chạy wsl --shutdown rồi mở lại Ubuntu. Xem thêm tài liệu mạng WSL của Microsoft.

    Linux. Trên Ubuntu 24.04, cài ROS 2 Jazzy theo cùng hướng dẫn trên với ros-jazzy-desktop, và cài SSH client nếu máy chưa có: sudo apt install openssh-client.

    2. SSH key tới Pi

    Trên Windows chạy các lệnh sau trong Ubuntu (WSL); trên Linux chạy trong terminal thường. Thay pi@robot.local bằng tài khoản và tên/IP của Pi:

    ssh-keygen -t ed25519            # bỏ qua nếu đã có key
ssh-copy-id pi@robot.local       # chép public key lên Pi, nhập mật khẩu Pi lần cuối
ssh pi@robot.local true          # đăng nhập một lần để chấp nhận host key

    Studio chạy SSH ở chế độ BatchMode: không hỏi, không lưu mật khẩu và không tự bỏ qua kiểm tra host key. Vì vậy, bước chấp nhận host key phải làm tay một lần.

    3. Tải và cài đặt

    Windows. Tải RPBotStudio.exe, đặt ở thư mục bất kỳ rồi nhấp đúp để chạy. File đã chứa Python, Tk và tài nguyên của app nên không cần cài thêm; có thể chép riêng file này sang máy khác.

    File chưa được ký số, nên lần đầu chạy Windows SmartScreen có thể hiện hộp thoại Windows protected your PC. Bấm More info, kiểm tra tên file, rồi bấm Run anyway. Muốn chắc file tải về còn nguyên vẹn, so mã SHA-256 với giá trị GitHub hiển thị cạnh tên file trên trang Releases:

    Get-FileHash .\RPBotStudio.exe -Algorithm SHA256

    Linux.

    sha256sum RPBotStudio-Linux-x86_64.tar.gz      # so với giá trị trên trang Releases
tar -xzf RPBotStudio-Linux-x86_64.tar.gz
cd RPBotStudio-Linux-x86_64
./install.sh                                   # cài vào ~/.local/share/rpbot-studio, thêm vào menu ứng dụng

    Mở RPBot Studio trong menu ứng dụng, hoặc chạy thẳng ./RPBotStudio mà không cần cài. Bản dựng sẵn cần glibc 2.39 (Ubuntu 24.04 trở lên); với Ubuntu cũ hơn, chạy từ mã nguồn.

    Chạy từ mã nguồn (Windows hoặc Linux, cần Python 3.10+ có tkinter; trên Linux cài sudo apt install python3-tk). App không dùng thư viện ngoài:

    git clone https://github.com/nguyenbinh-shark/rpbot-studio.git
cd rpbot-studio
python launch_rpbot.pyw          # Linux: python3 launch_rpbot.pyw

    4. Kết nối robot lần đầu

    Mở trang Kết nối và điền:

    • Thiết bị / IP: tên như robot.local hoặc IP của Pi.
    • Tài khoản SSH: user đăng nhập Pi.
    • Chỉ trên Windows: Ubuntu / WSL là tên distro có ROS 2 (mặc định Ubuntu-24.04); Tài khoản WSL là user chạy ROS, để trống để dùng user mặc định của WSL.

    Bấm Ping thiết bị để xem IP và số phản hồi: xanh lá là đủ phản hồi, vàng là mất gói, đỏ là không phân giải được tên. Ping không có phản hồi vẫn có thể thử SSH. Bấm Kết nối ngay; cấu hình được lưu trên PC và từ lần mở sau Studio tự kết nối.

    Nếu SSH được nhưng các ô cảm biến vẫn xám (chỉ Windows): tường lửa Hyper-V có thể đang chặn DDS vào WSL. Script configure_network.ps1 trong repo xử lý việc này. Tải script, chạy không tham số để xem cấu hình hiện tại, rồi chạy với -Apply trong PowerShell quyền Administrator để chỉ mở UDP DDS từ địa chỉ của Pi:

    Invoke-WebRequest https://raw.githubusercontent.com/nguyenbinh-shark/rpbot-studio/main/configure_network.ps1 -OutFile configure_network.ps1 -UseBasicParsing
powershell -ExecutionPolicy Bypass -File .\configure_network.ps1
powershell -ExecutionPolicy Bypass -File .\configure_network.ps1 -Apply -PiAddress 192.168.1.50

    Script tạo một rule tên RPBot-WSL-DDS-In cho UDP 7400–7525 (domain 0) chỉ từ IP của Pi, không đổi thiết lập tường lửa khác.

    5. Đọc bảng trạng thái

    Bảng ở đầu cửa sổ luôn hiện Kết nối, Chế độ, Nav2, Motor, các ô LiDAR / Odom / IMU / Motor FB và vận tốc. Màu luôn đi kèm nhãn chữ:

    MàuÝ nghĩa
    Xanh láDữ liệu mới, đã xác nhận
    Xanh dươngĐã phát hiện (ví dụ có action server Nav2) nhưng chưa xác nhận hoạt động
    VàngĐang chờ hoặc cần xử lý
    ĐỏMất kết nối, dữ liệu cũ hoặc lỗi
    XámChưa có dữ liệu

    Dòng cảnh báo dưới bảng nêu nguyên nhân và việc nên làm tiếp. Khi Tự kết nối / phục hồi bật (mặc định), Studio kiểm tra SSH nền mỗi 5–30 giây và tự nối lại khi robot sẵn sàng. Đóng Studio chỉ dừng bộ nhận dữ liệu trên PC; robot và RViz vẫn chạy.

    6. Tạo bản đồ (Mapping)

    1. Trang Mapping → Bắt đầu mapping. Nếu Pi đã có đúng một phiên mapping, Studio nối vào phiên đó thay vì mở thêm.
    2. Bấm Mở RViz · Map để xem map, LiDAR và robot.
    3. Lái robot quét hết khu vực bằng tay điều khiển RC. Studio không điều khiển chuyển động.
    4. Nhập tên rồi bấm Lưu map. Map được lưu thành cặp .yaml + .pgm trong ~/pi5-stm32-slam/maps/ trên Pi. Tên chỉ gồm chữ không dấu, số, - và _; trùng tên thì không ghi đè.
    5. Map bị lệch hoặc môi trường thay đổi: lưu map cũ nếu cần, rồi bấm Tạo map lại và xác nhận. SLAM bỏ map trong bộ nhớ và dựng lại từ các lần quét tiếp theo; file đã lưu giữ nguyên.
    6. Xong thì bấm Dừng tạo map. Phần map chưa lưu trong bộ nhớ sẽ mất.

    7. Quản lý bản đồ đã lưu

    • Tải lại danh sách để đọc thư viện map trên Pi: ngày lưu, kích thước, độ phân giải, ảnh xem trước.
    • Tải map về PC: chọn thư mục đích; Studio tạo thư mục con theo tên map chứa YAML/PGM, kiểm tra checksum và không ghi đè.
    • Đổi tên cập nhật cả YAML lẫn PGM. Chuyển vào thùng rác (có xác nhận) đưa map vào maps/.trash/ trên Pi, không xóa hẳn.
    • Nếu map đã thay đổi sau lần tải danh sách, thao tác bị từ chối để bạn tải lại danh sách trước.

    8. Điều hướng (Navigation)

    1. Đang Mapping thì lưu map cần giữ, bấm Dừng tạo map và chờ dừng xong.
    2. Trang Bản đồ đã lưu → chọn map.
    3. Trang Navigation → Bắt đầu Nav. Studio kiểm tra map chưa đổi và không mở trùng phiên.
    4. Bấm Mở RViz · Navigation, dùng 2D Pose Estimate để đặt vị trí và hướng hiện tại của robot. Chờ ô Nav2 chuyển xanh lá rồi mới chọn đích trong RViz.
    5. Xong thì bấm Dừng Nav. Sau đó có thể quay lại Mapping.

    Phiên Navigation do Studio mở chạy dưới dịch vụ rpbot-navigation.service trên Pi với allow_motor_enable:=false và không tự chạy lại sau khi Pi khởi động lại.

    9. Dừng tác vụ, Debug và nhật ký

    NútPhạm vi
    Dừng tạo map (trang Mapping)Phiên Mapping trong domain đã chọn và tiến trình con
    Dừng Nav (trang Navigation)Phiên Navigation trong domain đã chọn và tiến trình con
    Dừng tất cả tác vụ robot (luôn ở góc trên)Mọi launch robot và ghi/phát bag của dự án trong domain đã chọn
    Dừng tác vụ đã chọn (trang Tác vụ)Chỉ các dòng được chọn; giữ Ctrl để chọn nhiều dòng

    Trước khi dừng, Studio liệt kê chế độ, tên bag và PID để bạn xác nhận; bấm hủy thì không dừng gì. Tiến trình được dừng bằng SIGINT trước, SIGTERM sau. Domain mặc định là 0, đổi được ở trang Tác vụ và tự cập nhật theo phiên đang kết nối.

    Trang Debug hiện số bản tin, tuổi dữ liệu và trạng thái từng topic (/map, /scan, /odom, /imu/data, /motor_fb, /motor_status, TF map → base_footprint). Nút Đọc log robot đọc log dịch vụ Mapping/Navigation trên Pi; Mở thư mục log PC mở thư mục cấu hình và log trên máy tính. Nhật ký thao tác nằm ở cuối cửa sổ, kéo thanh phân cách để đổi chiều cao. Ô chọn Tiếng Việt / English ở thanh trên cùng đổi ngôn ngữ ngay mà không nối lại SSH/ROS.

    10. Tự khởi động mapping khi Pi bật (tùy chọn)

    Cần bản mã nguồn trên PC và Studio đã kết nối thành công một lần (lệnh dùng lại cấu hình đã lưu). Trên Pi, bật linger cho tài khoản SSH để dịch vụ user chạy được khi chưa đăng nhập:

    sudo loginctl enable-linger pi          # chạy trên Pi, thay pi bằng tài khoản SSH

    Sau đó, trên PC, trong thư mục mã nguồn:

    python check_connection.py --install-autostart

    Lệnh chỉ enable dịch vụ rpbot-mapping.service (chạy scripts/run.sh mapping allow_motor_enable:=false, domain 0), không khởi động lại phiên đang chạy. Tắt tự chạy bằng lệnh trên Pi: systemctl --user disable rpbot-mapping.service.

    An toàn

    • Studio không bao giờ gửi lệnh bật động cơ hay lệnh vận tốc. Phiên do Studio mở luôn có allow_motor_enable:=false; robot có được chạy hay không phụ thuộc firmware và tay điều khiển RC.
    • Bắt đầu Nav không gửi đích; đích chỉ được chọn trong RViz.
    • Các nút dừng chỉ tác động lên tiến trình ROS/bag của dự án trong domain đã chọn, có kiểm tra lại PID và thời điểm khởi tạo trước khi gửi tín hiệu. Chương trình khác trên Pi không bị ảnh hưởng.
    • Thao tác đang chạy dở bị hủy nếu mất mạng giữa chừng và không tự gửi lại khi mạng trở lại.

    Dùng với robot khác

    Studio nhận diện phiên ROS và thao tác trên Pi theo các quy ước của RPBot. Một robot khác dùng được Studio khi có cùng giao diện sau; nếu khác, cần sửa remote_ops.py, ros_session.py và robot_status.py trong mã nguồn.

    Features

    • Auto connect: checks SSH to the Pi, finds the running Mapping/Navigation session, picks up that session’s ROS domain and Fast DDS profile, and reconnects after network drops.
    • Always-visible status panel: connection, mode, map, Nav2, motors, LiDAR / Odom / IMU / Motor FB tiles and the v, ω velocities, refreshed about five times per second. Data older than 2 seconds is flagged as stale instead of showing outdated readings.
    • Mapping: start a session, open a preconfigured RViz, save the map on the Pi, restart mapping, stop the session.
    • Saved maps: list with previews; download to the PC with checksum verification; rename; move to trash. Nothing overwrites an existing file.
    • Navigation: run Nav2 on the chosen map and open RViz Navigation to set the initial pose and goals.
    • Tasks and Debug: list and stop running launches/bags; per-topic data age; read the robot’s service logs.
    • Vietnamese / English UI, switchable while running.

    What you need

    PartRequirement
    Windows PCWindows 10/11 x64; WSL 2 with Ubuntu 24.04 and ROS 2 Jazzy including RViz; an SSH key inside WSL
    Linux PCUbuntu 24.04 or newer, x86_64; ROS 2 Jazzy including RViz; ssh
    RobotRaspberry Pi 5, Ubuntu 24.04, ROS 2 Jazzy; a built ~/pi5-stm32-slam workspace (SLAM Toolbox, Nav2, PyYAML); the STM32 running Microros_H723_USB
    NetworkPC and Pi on the same LAN. robot.local names need mDNS, otherwise use the IP. DDS domain 0 uses UDP 7400–7649

    [!IMPORTANT] Before you install

    Studio drives the RPBot robot-side software. The pi5-stm32-slam workspace on the Pi is not public yet. If your robot runs a different ROS 2 stack, see Using another robot for what Studio expects.

    Quick start

    1. Install ROS 2 Jazzy with RViz on the PC. On Windows, ROS runs inside WSL 2.
    2. Create an SSH key, copy it to the Pi and log in once to accept the host key.
    3. Download RPBot Studio for your OS from the box above and open it.
    4. On the Connect page, enter the Pi’s name or IP and the SSH user, then click Connect now.
    5. Build a map on the Mapping page, save it, then run Navigation on it.

    The sections below go through each step.

    1. Prepare the PC

    Windows. In an Administrator PowerShell, install Ubuntu 24.04 in WSL:

    wsl --install -d Ubuntu-24.04

    Inside Ubuntu, install ROS 2 Jazzy with the ros-jazzy-desktop package by following the official ROS 2 instructions; the package includes RViz.

    Turn on WSL mirrored networking so that DDS traffic from the Pi reaches WSL. It needs Windows 11 22H2 or newer; on Windows 10, WSL uses NAT networking, so ROS data from the Pi usually does not reach Studio even though SSH works. Create or edit %UserProfile%\.wslconfig:

    [wsl2]
networkingMode=mirrored

    Then run wsl --shutdown and reopen Ubuntu. See Microsoft’s WSL networking docs.

    Linux. On Ubuntu 24.04, install ROS 2 Jazzy the same way with ros-jazzy-desktop, plus the SSH client if missing: sudo apt install openssh-client.

    2. SSH key to the Pi

    On Windows run these inside Ubuntu (WSL); on Linux use a normal terminal. Replace pi@robot.local with your Pi’s user and name or IP:

    ssh-keygen -t ed25519            # skip if you already have a key
ssh-copy-id pi@robot.local       # copy the public key (the last time you type the Pi password)
ssh pi@robot.local true          # log in once to accept the host key

    Studio runs SSH in BatchMode: it never asks for or stores passwords and never skips host key checks, so the host key must be accepted by hand once.

    3. Download and install

    Windows. Download RPBotStudio.exe, put it in any folder and double-click it. Python, Tk and the app’s resources are bundled, so nothing else needs installing; the file can be copied to another PC on its own.

    The file is not code-signed, so on first launch Windows SmartScreen may show Windows protected your PC. Click More info, check the file name, then Run anyway. To confirm the download is intact, compare its SHA-256 with the value GitHub shows next to the file on the Releases page:

    Get-FileHash .\RPBotStudio.exe -Algorithm SHA256

    Linux.

    sha256sum RPBotStudio-Linux-x86_64.tar.gz      # compare with the Releases page
tar -xzf RPBotStudio-Linux-x86_64.tar.gz
cd RPBotStudio-Linux-x86_64
./install.sh                                   # installs to ~/.local/share/rpbot-studio and adds a menu entry

    Open RPBot Studio from the application menu, or run ./RPBotStudio without installing. The prebuilt binary needs glibc 2.39 (Ubuntu 24.04+); on older releases, run from source.

    From source (Windows or Linux, Python 3.10+ with tkinter; on Linux sudo apt install python3-tk). The app has no third-party dependencies:

    git clone https://github.com/nguyenbinh-shark/rpbot-studio.git
cd rpbot-studio
python launch_rpbot.pyw          # Linux: python3 launch_rpbot.pyw

    4. First connection

    Open the Connect page and fill in:

    • Device / IP: a name such as robot.local or the Pi’s IP.
    • SSH user: the Pi login.
    • Windows only: Ubuntu / WSL is the distro that has ROS 2 (default Ubuntu-24.04); WSL user is the user that runs ROS, leave it empty for the WSL default user.

    Click Ping device to see the IP and reply count: green means all replies, amber means packet loss, red means the name did not resolve. SSH can still work without ping replies. Click Connect now; the settings are saved on the PC and Studio reconnects on its own next time.

    SSH works but the sensor tiles stay gray (Windows only): the Hyper-V firewall may be blocking DDS into WSL. The repository’s configure_network.ps1 handles this. Download it, run it without arguments to inspect the current setup, then run it with -Apply in an Administrator PowerShell to open DDS UDP from the Pi’s address only:

    Invoke-WebRequest https://raw.githubusercontent.com/nguyenbinh-shark/rpbot-studio/main/configure_network.ps1 -OutFile configure_network.ps1 -UseBasicParsing
powershell -ExecutionPolicy Bypass -File .\configure_network.ps1
powershell -ExecutionPolicy Bypass -File .\configure_network.ps1 -Apply -PiAddress 192.168.1.50

    The script adds one rule, RPBot-WSL-DDS-In, for UDP 7400–7525 (domain 0) from the Pi’s IP only, and leaves other firewall settings unchanged.

    5. Reading the status panel

    The panel at the top always shows Connection, Mode, Nav2, Motor, the LiDAR / Odom / IMU / Motor FB tiles and the velocities. Colors always come with a text label:

    ColorMeaning
    GreenFresh, confirmed data
    BlueDetected (for example a Nav2 action server) but not confirmed active
    AmberWaiting or needs attention
    RedDisconnected, stale data or an error
    GrayNo data yet

    The line below the panel states the cause and the next step. With Auto connect / recover on (the default), Studio checks SSH in the background every 5–30 seconds and reconnects when the robot is reachable. Closing Studio only stops its receiver on the PC; the robot and RViz keep running.

    6. Mapping

    1. Mapping page → Start mapping. If exactly one mapping session is already running on the Pi, Studio attaches to it instead of starting another.
    2. Click Open RViz · Map to see the map, LiDAR and robot.
    3. Drive the robot around the area with the RC transmitter. Studio does not control motion.
    4. Enter a name and click Save map. The map is stored as a .yaml + .pgm pair in ~/pi5-stm32-slam/maps/ on the Pi. Names use unaccented letters, digits, - and _; existing names are never overwritten.
    5. If the map drifts or the space changes, save the old map if needed, then click Restart mapping and confirm. SLAM drops the in-memory map and rebuilds from new scans; saved files stay.
    6. Click Stop mapping when done. Any unsaved in-memory map is lost.

    7. Saved maps

    • Refresh list reads the map library on the Pi: save date, size, resolution and preview.
    • Download map to PC: choose a folder; Studio creates a subfolder named after the map with the YAML/PGM files, verifies checksums and never overwrites.
    • Rename updates both YAML and PGM. Move to trash (with confirmation) moves the map to maps/.trash/ on the Pi instead of deleting it.
    • If a map changed after the list was loaded, the action is refused until you refresh the list.

    8. Navigation

    1. If mapping is running, save the map you need, click Stop mapping and wait for it to stop.
    2. Saved maps page → select a map.
    3. Navigation page → Start Nav. Studio checks that the map has not changed and never opens a duplicate session.
    4. Click Open RViz · Navigation and use 2D Pose Estimate to set the robot’s current position and heading. Wait for the Nav2 tile to turn green before choosing a goal in RViz.
    5. Click Stop Nav when finished. Mapping can be started again afterwards.

    Navigation sessions opened by Studio run as rpbot-navigation.service on the Pi with allow_motor_enable:=false and do not restart after the Pi reboots.

    9. Stopping tasks, Debug and logs

    ButtonScope
    Stop mapping (Mapping page)Mapping sessions in the selected domain and their child processes
    Stop Nav (Navigation page)The Navigation session in the selected domain and its child processes
    Stop all robot tasks (always at the top)All of the project’s robot launches and bag record/play in the selected domain
    Stop selected tasks (Tasks page)Only the selected rows; hold Ctrl to select several

    Before stopping, Studio lists the mode, bag name and PID for confirmation; cancelling stops nothing. Processes get SIGINT first, then SIGTERM. The domain defaults to 0, can be changed on the Tasks page and follows the connected session.

    The Debug page shows message counts, data age and state for each topic (/map, /scan, /odom, /imu/data, /motor_fb, /motor_status, TF map → base_footprint). Read robot logs reads the Mapping/Navigation service logs on the Pi; Open PC log folder opens the settings and log folder on the computer. The activity log sits at the bottom of the window; drag the divider to resize it. The language selector in the top bar switches the UI immediately without reconnecting SSH or ROS.

    10. Start mapping at boot (optional)

    This needs the source checkout on the PC and one successful Studio connection (the command reuses the saved settings). On the Pi, enable lingering for the SSH user so user services run without a login:

    sudo loginctl enable-linger pi          # on the Pi; replace pi with the SSH user

    Then on the PC, in the source folder:

    python check_connection.py --install-autostart

    The command only enables rpbot-mapping.service (which runs scripts/run.sh mapping allow_motor_enable:=false in domain 0) and does not restart a running session. Turn it off on the Pi with systemctl --user disable rpbot-mapping.service.

    Safety

    • Studio never sends motor-enable or velocity commands. Sessions it starts always use allow_motor_enable:=false; whether the robot may move depends on the firmware and the RC transmitter.
    • Start Nav sends no goal; goals are only set in RViz.
    • Stop buttons only affect the project’s ROS/bag processes in the selected domain, and recheck the PID and start time before signalling. Other programs on the Pi are untouched.
    • An operation interrupted by a network drop is cancelled and is not replayed when the network returns.

    Troubleshooting

    SymptomFix
    Windows blocks the file (SmartScreen)Click More info → Run anyway. The file is unsigned; verify its SHA-256 as in Download and install.
    Ping shows red “could not resolve”The network blocks mDNS: enter the Pi’s IP instead of xxx.local.
    SSH fails with Permission denied or Host key verification failedRedo SSH key to the Pi; on Windows do it inside WSL.
    SSH works but sensor tiles are gray or redDDS is blocked: check WSL mirrored mode, run configure_network.ps1, make sure PC and Pi share the LAN.
    “Install ros-jazzy-rviz2 on the PC”Install ros-jazzy-desktop in WSL (Windows) or on the Linux PC.
    “Build pi5-stm32-slam on the Pi first”The ~/pi5-stm32-slam workspace is missing or not built on the Pi.
    Nav2 tile is blue but the robot does not moveNav2 is not active yet: set 2D Pose Estimate in RViz and wait for green.
    Data keeps showing as staleThe PC receiver restarts after 8 seconds without data; if it persists, check the Debug page and Read robot logs.
    The Linux build does not start on an older UbuntuThe binary needs glibc 2.39 (Ubuntu 24.04+); run from source.

    When reporting a problem on GitHub Issues, include the activity log and the PC’s operating system.

    Using another robot
