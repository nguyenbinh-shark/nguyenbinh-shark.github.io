    DAPLink Flasher — nạp STM32H723 qua mạch nạp không dây, mất link vẫn nạp tiếp DAPLink Flasher — resumable STM32H723 flashing over a wireless probe

    Ngày đăng:Published: 18/10/2026October 18, 2026

    DAPLink Flasher nạp firmware cho STM32H723 qua mạch nạp CMSIS-DAP / DAPLink, làm riêng cho đường truyền hay rớt như DAPLink không dây. Mất link giữa chừng thì app tự kết nối lại và nạp tiếp từ chỗ đang dở, không xóa lại từ đầu. Bản Windows là một file EXE đã kèm OpenOCD.DAPLink Flasher programs an STM32H723 through a CMSIS-DAP / DAPLink probe and is built for flaky links such as wireless DAPLink. When the link drops mid-write, it reconnects and resumes where it stopped instead of erasing everything again. The Windows build is a single EXE with OpenOCD bundled.

    Vì sao không dùng thẳng openocd program?

    openocd -c program làm lại từ đầu mỗi khi link rớt, và mỗi lần thất bại để flash ở trạng thái xóa dở. Với mạch nạp không dây, việc này lặp lại nhiều lần.

    DAPLink Flasher giữ một phiên OpenOCD và điều khiển qua cổng Tcl RPC. Flash được ghi theo từng sector 128 KB, mỗi lần một khối 8 KB. Mỗi sector được kiểm tra bằng CRC tính ngay trên chip (verify_image_checksum): sector đã đúng thì bỏ qua; link rớt thì chỉ mất khối đang ghi. Lần nạp sau xác định khối đó đã ghi, chưa ghi hay ghi dở rồi nạp tiếp.

    Tính năng

    • Nạp file .elf, .hex hoặc .bin (.bin ghi từ 0x08000000). Phần nằm ngoài flash được bỏ qua và ghi chú trong nhật ký.
    • Bản đồ 8 sector (S0–S7) cho biết từng sector đang chờ, đang xóa, đang ghi, đã qua CRC, đã khớp sẵn hay không cần ghi.
    • Tự đổi giao tiếp và xung SWD khi không mở được phiên; mặc định thử lần lượt hid 1000 kHz, hid 400 kHz, usb_bulk 1000 kHz.
    • Giới hạn thời gian cho một lần nạp; nút Dừng nạp luôn dùng được.
    • Tùy chọn đọc /motor_status của robot trước khi dừng chip (bật mặc định).
    • Nạp xong thì reset STM32 để chạy firmware mới. Không cần nối chân NRST: app reset qua SWD.
    • Giao diện sáng/tối theo Windows, Tiếng Việt / English đổi ngay khi đang chạy; CLI dùng chung bộ máy nạp với giao diện.

    [!IMPORTANT] Chỉ hỗ trợ STM32H723

    Địa chỉ flash, kích thước sector, mã nhận dạng chip và file target của OpenOCD được viết cố định cho STM32H723. App đọc IDCODE và không nạp nếu chip không thuộc dòng STM32H72x/73x. Muốn dùng cho chip khác, xem mục Dùng với chip khác.

    Bắt đầu nhanh

    1. Tải bản cho hệ điều hành của bạn ở khung phía trên. Linux: cài thêm OpenOCD và udev rule.
    2. Cắm dongle mạch nạp vào PC, cấp nguồn cho robot hoặc board STM32H723.
    3. Mở app, chọn mạch nạp (hoặc để Tự động (mạch nạp đầu tiên)) và bấm Chọn file… để chọn firmware.
    4. Không dùng robot RPBot thì bỏ chọn Kiểm tra động cơ trước khi dừng chip.
    5. Bấm Nạp firmware và chờ dòng Nạp xong, CRC từng sector đều đúng.

    1. Cài đặt

    Windows. Tải DAPLinkFlasher.exe, đặt ở đâu cũng được rồi nhấp đúp để chạy. Không cần STM32CubeIDE; có thể chép riêng file này sang PC khác.

    File chưa được ký số, nên lần đầu chạy Windows SmartScreen có thể hiện Windows protected your PC. Bấm More info, kiểm tra tên file, rồi bấm Run anyway. Để chắc file còn nguyên vẹn, so mã SHA-256 với giá trị GitHub hiển thị cạnh tên file trên trang Releases:

    Get-FileHash .\DAPLinkFlasher.exe -Algorithm SHA256

    Linux.

    sudo apt install openocd
sha256sum DAPLinkFlasher-Linux-x86_64.tar.gz     # so với giá trị trên trang Releases
tar -xzf DAPLinkFlasher-Linux-x86_64.tar.gz
cd DAPLinkFlasher-Linux-x86_64
./install.sh --udev     # cài vào ~/.local/share/dap-flasher, thêm vào menu, cấp quyền USB (hỏi mật khẩu sudo)

    Cắm lại mạch nạp sau khi cài udev rule, rồi mở DAPLink Flasher trong menu ứng dụng hoặc chạy ./DAPLinkFlasher. Không chạy app bằng sudo. Rule được đặt ở /etc/udev/rules.d/60-dap-flasher.rules và chỉ gồm hai mạch nạp ở bảng trên; mạch nạp khác cần thêm cặp VID:PID của nó vào file này.

    Chạy từ mã nguồn (Python 3.10+ có tkinter và OpenOCD; hidapi không bắt buộc, chỉ dùng để liệt kê mạch nạp):

    git clone https://github.com/nguyenbinh-shark/daplink-flasher.git
cd daplink-flasher
python -m pip install hidapi      # tùy chọn
python dap_flasher.pyw            # Linux: python3 dap_flasher.pyw

    App tìm OpenOCD theo thứ tự: biến môi trường OPENOCD (kèm OPENOCD_SCRIPTS), bản đóng gói trong EXE, openocd trên PATH, rồi bản đi kèm STM32CubeIDE (C:\ST\STM32CubeIDE_* trên Windows; /opt/st/stm32cubeide_* hoặc ~/st/stm32cubeide_* trên Linux).

    2. Nạp firmware

    Ba ô ở đầu cửa sổ luôn cho biết kết nối mạch nạp, firmware đã chọn và trạng thái kiểm tra động cơ. Màu luôn đi kèm nhãn chữ. Chọn được file không có nghĩa chip đã được nạp.

    1. Kết nối mạch nạp. Cắm dongle, chọn mạch nạp trong danh sách hoặc để Tự động (mạch nạp đầu tiên); bấm Quét lại nếu chưa thấy. Nút Kết nối chỉ kiểm tra đường truyền, không dừng chip; có thể bỏ qua bước này và bấm nạp luôn.
    2. Chọn firmware. Bấm Chọn file… và chọn .elf, .hex hoặc .bin. Ô firmware hiện kích thước, các sector sẽ ghi và thời điểm build.
    3. Thông số nạp:
      • Giao tiếp: hid ổn định nhất với DAPLink không dây; ngoài ra có usb_bulk và auto.
      • SWD · kHz: xung SWD. Link không dây yếu thì dùng 400.
      • Tối đa · phút: bỏ cuộc nếu quá thời gian này.
      • Tự đổi giao tiếp / xung khi mất link: thử lần lượt các cặp giao tiếp và xung.
      • Ghi lại cả sector đã đúng: tắt cơ chế bỏ qua sector đã khớp, ghi toàn bộ.
      • Kiểm tra động cơ trước khi dừng chip: xem mục 3.
    4. Bấm Nạp firmware. Theo dõi phần trăm, tốc độ, thời gian và trạng thái từng sector. Link rớt thì app tự kết nối lại và nạp tiếp. Dừng nạp dừng được bất cứ lúc nào; bấm Nạp firmware lần nữa sẽ nạp tiếp từ chỗ đang dở.
    5. Khi dòng Nạp xong, CRC từng sector đều đúng hiện ra, STM32 đã được reset và chạy firmware mới.

    Nút Reset STM32 reset và cho chip chạy mà không nạp. Bật kèm log OpenOCD để xem đầu ra gốc của OpenOCD trong nhật ký; thanh phía trên nhật ký kéo được để đổi chiều cao.

    [!WARNING] App đóng các phiên OpenOCD khác

    Để giành mạch nạp, mặc định app đóng mọi tiến trình OpenOCD đang chạy trên máy (taskkill trên Windows, pkill trên Linux), kể cả phiên debug của STM32CubeIDE. Lưu công việc debug trước khi nạp, hoặc tắt hành vi này bằng "kill_other_openocd": false trong file cấu hình (mục Cấu hình).

    3. Kiểm tra động cơ trước khi dừng chip

    Trên robot RPBot, dừng (halt) MCU khi động cơ đang bật có thể để động cơ RobStride tiếp tục chạy ở vận tốc đặt cuối cùng. Vì vậy, khi tùy chọn này bật (mặc định), app chỉ dừng chip đang chạy sau khi lệnh kiểm tra cho thấy bit 0x10 (MOTORS_ENABLED) của /motor_status bằng 0:

    • Động cơ đang bật: app ghi cảnh báo và chờ, kiểm tra lại mỗi 5 giây cho tới khi bạn disarm trên tay RC.
    • Không đọc được /motor_status: app hỏi lại; chỉ tiếp tục khi bạn chắc chắn động cơ đã tắt.

    Lệnh mặc định SSH vào Pi của robot và in giá trị /motor_status. Trên Windows, lệnh có thêm tiền tố wsl -- để chạy SSH trong WSL:

    ssh -o BatchMode=yes -o ConnectTimeout=5 pi@robot.local "source /opt/ros/jazzy/setup.bash; ROS_DOMAIN_ID=0 timeout -k 1 6 ros2 topic echo /motor_status std_msgs/msg/UInt8 --once --field data --no-daemon --spin-time 2 2>/dev/null | head -1"

    Bấm Sửa lệnh kiểm tra động cơ để thay pi@robot.local bằng tài khoản và tên/IP Pi của bạn. Lệnh cần SSH key, không dùng mật khẩu (cách tạo key: hướng dẫn RPBot Studio). Lệnh nào cũng được, miễn là in ra một số thập phân. Robot không phải RPBot, hoặc board không nối động cơ, thì bỏ chọn tùy chọn này.

    4. Dòng lệnh (CLI)

    CLI dùng chung bộ máy nạp và cấu hình đã lưu với giao diện:

    python dap_flasher.pyw --cli firmware.elf        # nạp
python dap_flasher.pyw --link-test               # chỉ đo chất lượng link (20 lần đọc), không dừng chip
python dap_flasher.pyw --reset                   # reset và chạy STM32

    Trên Linux, bản đóng gói nhận cùng tham số: ./DAPLinkFlasher --cli firmware.elf.

    Trên Windows nên chạy CLI từ mã nguồn như trên. DAPLinkFlasher.exe là ứng dụng cửa sổ nên không in log khi gọi thẳng từ terminal. Muốn dùng EXE trong PowerShell thì nối thêm | Out-Host để PowerShell chờ app chạy xong và hiện log:

    [Console]::OutputEncoding = [Text.Encoding]::UTF8     # để chữ tiếng Việt trong log hiện đúng

    Why not just openocd program?

    openocd -c program starts over every time the link drops, and each failure leaves the flash half-erased. With a wireless probe that can happen again and again.

    DAPLink Flasher keeps one OpenOCD session and drives it over the Tcl RPC port. It writes one 128 KB sector at a time in 8 KB chunks. Every sector is checked with a CRC computed on the chip (verify_image_checksum): sectors that already match are skipped, and a link drop only costs the chunk being written. The next run works out whether that chunk was written, not written or partly written, and carries on.

    Features

    • Flashes .elf, .hex or .bin (.bin is written from 0x08000000). Data outside the flash is skipped and noted in the log.
    • An 8-sector map (S0–S7) shows each sector as waiting, erasing, writing, CRC OK, already matching or unused.
    • Switches interface and SWD clock when a session cannot be opened; by default it tries hid 1000 kHz, hid 400 kHz, then usb_bulk 1000 kHz.
    • A time limit per run; Stop flashing is always available.
    • Optional /motor_status check on the robot before halting the chip (on by default).
    • Resets the STM32 into the new firmware when done. NRST does not need to be wired: reset goes over SWD.
    • Light/dark theme following Windows, Vietnamese / English switchable while running; the CLI shares the flashing engine with the GUI.

    [!IMPORTANT] STM32H723 only

    The flash address, sector size, chip ID and OpenOCD target file are fixed for the STM32H723. The app reads the IDCODE and will not flash a chip outside the STM32H72x/73x line. To target another chip, see Using another chip.

    Quick start

    1. Download the build for your OS from the box above. On Linux, also install OpenOCD and the udev rule.
    2. Plug the probe dongle into the PC and power the robot or the STM32H723 board.
    3. Open the app, pick the probe (or leave Automatic (first probe)) and click Browse… to choose the firmware.
    4. If this is not an RPBot robot, untick Check motors before halting the chip.
    5. Click Flash firmware and wait for Flash complete, all sector CRCs verified.

    1. Install

    Windows. Download DAPLinkFlasher.exe, put it anywhere and double-click it. STM32CubeIDE is not needed, and the file can be copied to another PC on its own.

    The file is not code-signed, so on first launch Windows SmartScreen may show Windows protected your PC. Click More info, check the file name, then Run anyway. To confirm the download is intact, compare its SHA-256 with the value GitHub shows next to the file on the Releases page:

    Get-FileHash .\DAPLinkFlasher.exe -Algorithm SHA256

    Linux.

    sudo apt install openocd
sha256sum DAPLinkFlasher-Linux-x86_64.tar.gz     # compare with the Releases page
tar -xzf DAPLinkFlasher-Linux-x86_64.tar.gz
cd DAPLinkFlasher-Linux-x86_64
./install.sh --udev     # installs to ~/.local/share/dap-flasher, adds a menu entry and USB access (asks for sudo)

    Replug the probe after installing the udev rule, then open DAPLink Flasher from the application menu or run ./DAPLinkFlasher. Do not run the app with sudo. The rule lives in /etc/udev/rules.d/60-dap-flasher.rules and covers only the two probes listed above; add your probe’s VID:PID there if it differs.

    From source (Python 3.10+ with tkinter, plus OpenOCD; hidapi is optional and only fills the probe list):

    git clone https://github.com/nguyenbinh-shark/daplink-flasher.git
cd daplink-flasher
python -m pip install hidapi      # optional
python dap_flasher.pyw            # Linux: python3 dap_flasher.pyw

    OpenOCD is looked up in this order: the OPENOCD environment variable (with OPENOCD_SCRIPTS), the copy bundled in the EXE, openocd on PATH, then the copy shipped with STM32CubeIDE (C:\ST\STM32CubeIDE_* on Windows; /opt/st/stm32cubeide_* or ~/st/stm32cubeide_* on Linux).

    2. Flashing

    The three cards at the top always show the probe connection, the selected firmware and the motor check state. Colors always come with a text label. Having a file selected does not mean the chip has been flashed.

    1. Connect probe. Plug in the dongle and pick the probe from the list, or leave Automatic (first probe); click Refresh if it is missing. Connect only tests the link and does not halt the chip; you can skip it and flash right away.
    2. Select firmware. Click Browse… and choose an .elf, .hex or .bin. The firmware card shows the size, the sectors to be written and the build time.
    3. Flash settings:
      • Interface: hid is the most reliable with wireless DAPLink; usb_bulk and auto are also available.
      • SWD · kHz: the SWD clock. Use 400 on a weak wireless link.
      • Timeout · min: give up after this long.
      • Auto switch interface / clock on link loss: cycle through interface/clock pairs.
      • Rewrite sectors that already match: disable skipping and write everything.
      • Check motors before halting the chip: see section 3.
    4. Click Flash firmware. Watch the percentage, speed, elapsed time and per-sector state. If the link drops, the app reconnects and carries on. Stop flashing works at any time; clicking Flash firmware again resumes where it stopped.
    5. When Flash complete, all sector CRCs verified appears, the STM32 has been reset into the new firmware.

    Reset STM32 resets the chip and lets it run without flashing. Tick include OpenOCD log to see OpenOCD’s raw output in the activity log; drag the bar above the log to resize it.

    [!WARNING] The app closes other OpenOCD sessions

    To claim the probe, the app by default kills every running OpenOCD process on the PC (taskkill on Windows, pkill on Linux), including an STM32CubeIDE debug session. Save your debugging work first, or turn this off with "kill_other_openocd": false in the settings file (see Settings).

    3. Motor check before halting the chip

    On the RPBot robot, halting the MCU while the motors are enabled can leave the RobStride motors running at their last commanded speed. With this option on (the default), the app only halts a running chip after the check command shows bit 0x10 (MOTORS_ENABLED) of /motor_status is 0:

    • Motors enabled: the app logs a warning and waits, rechecking every 5 seconds until you disarm on the RC transmitter.
    • /motor_status unreadable: the app asks you; continue only if you are sure the motors are off.

    The default command logs in to the robot’s Pi over SSH and prints /motor_status. On Windows it is prefixed with wsl -- so that SSH runs inside WSL:

    ssh -o BatchMode=yes -o ConnectTimeout=5 pi@robot.local "source /opt/ros/jazzy/setup.bash; ROS_DOMAIN_ID=0 timeout -k 1 6 ros2 topic echo /motor_status std_msgs/msg/UInt8 --once --field data --no-daemon --spin-time 2 2>/dev/null | head -1"

    Click Edit motor check command to replace pi@robot.local with your Pi’s user and name or IP. It needs an SSH key, not a password (key setup: RPBot Studio guide). Any command works as long as it prints a decimal number. For robots other than RPBot, or boards without motors, untick the option.

    4. Command line (CLI)

    The CLI shares the flashing engine and the saved settings with the GUI:

    python dap_flasher.pyw --cli firmware.elf        # flash
python dap_flasher.pyw --link-test               # only measure link quality (20 reads), no halt
python dap_flasher.pyw --reset                   # reset and run the STM32

    On Linux the packaged build takes the same arguments: ./DAPLinkFlasher --cli firmware.elf.

    On Windows, run the CLI from source as above. DAPLinkFlasher.exe is a windowed app and prints nothing when called straight from a terminal. To use the EXE in PowerShell, append | Out-Host so PowerShell waits for it and shows the log:

    [Console]::OutputEncoding = [Text.Encoding]::UTF8     # shows the Vietnamese log text correctly
.\DAPLinkFlasher.exe --cli firmware.elf | Out-Host
    OptionMeaning
    --probe SERIALProbe serial number (default: first probe)
    --backend MODEInterface: hid, usb_bulk or auto
    --speed KHZSWD clock
    --no-rotateKeep the chosen interface/clock on failures
    --minutes NGive up after N minutes
    --forceRewrite sectors that already match
    --no-safetySkip the /motor_status check

    Troubleshooting

    SymptomFix
    Windows blocks the file (SmartScreen)Click More info → Run anyway. The file is unsigned; verify its SHA-256 as in Install.
    CMD_INFO failedThe robot-side DAPLink module is not paired with the dongle: power-cycle the robot-side module.
    command mismatch at the default clock or with usb_bulkUse hid at 400 kHz (GUI: Interface hid, SWD 400; CLI: --backend hid --speed 400).
    The probe is not listedReplug the dongle and click Refresh. On Linux run ./install.sh --udev and replug.
    “OpenOCD not found”Windows: use the packaged EXE or install STM32CubeIDE. Linux: sudo apt install openocd. Or set OPENOCD.
    Another OpenOCD holds the probeBy default the app closes other OpenOCD processes first. If you turned that off, close the STM32CubeIDE debug session.
    The app waits forever at the motor checkMotors are enabled: disarm on the RC transmitter. If the value cannot be read, check the command (SSH key, Pi name, ROS domain).
    The app was closed mid-flashReopen it, choose the same file and click Flash firmware: matching sectors are skipped.

    When reporting a problem on GitHub Issues, tick include OpenOCD log, flash once more and attach the log, the probe model and the operating system.

    Settings, updates and uninstall

    Settings (file, probe, interface, check command, theme, language) are saved automatically:

     WindowsLinux
    Settings file%APPDATA%\dap_flasher\settings.json~/.config/dap_flasher/settings.json
    UpdateDownload the new DAPLinkFlasher.exe and replace the old oneExtract the new archive and rerun ./install.sh
    UninstallDelete the EXE; delete the dap_flasher folder if you do not need the settings./install.sh --uninstall; remove the udev rule with sudo rm /etc/udev/rules.d/60-dap-flasher.rules

    To stop the app from closing other OpenOCD sessions, close the app and change "kill_other_openocd": true to false in the settings file.

    Using another chip

    Every chip-specific value sits at the top of dap_flasher.pyw: FLASH_BASE, SECTOR_SIZE, SECTOR_COUNT, FLASH_WORD, the DEV_ID_H72X chip ID and the OpenOCD target setup OPENOCD_TARGET_CFG (target/stm32h7x.cfg). Another chip needs these changed to match its flash layout; try it on a board with nothing connected before real use.

    Source, build and tests

    The source is at github.com/nguyenbinh-shark/daplink-flasher. The whole app lives in dap_flasher.pyw; translations are in ui_translations.py.

    # Windows: needs STM32CubeIDE for ST's OpenOCD (or set OPENOCD and OPENOCD_SCRIPTS); produces dist\DAPLinkFlasher.exe
python -m pip install -r requirements-build.txt
powershell -ExecutionPolicy Bypass -File .\build_dap_flasher.ps1

    # Linux (Ubuntu 24.04, bare metal or WSL): produces dist/linux/DAPLinkFlasher-Linux-x86_64.tar.gz
sudo apt install python3-tk python3-venv binutils
bash packaging/linux/build.sh

# Unit tests: file parsing, sector split, settings, OpenOCD lookup, translations; no USB or SWD access
python -m unittest discover -s tests -v

    The Windows build redistributes STMicroelectronics’ OpenOCD and scripts from STM32CubeIDE unmodified. OpenOCD is GPL-2.0-or-later; ST’s source is at github.com/STMicroelectronics/OpenOCD. The Linux build does not bundle OpenOCD.
